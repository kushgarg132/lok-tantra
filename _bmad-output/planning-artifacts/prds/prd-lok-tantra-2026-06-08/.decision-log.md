# Decision Log — Politician Hierarchy & Historical Power Explorer

Canonical memory and audit trail for this PRD run. Every decision, change, and override is recorded here as it happens.

## 2026-06-08

- **Intent**: Create (no prior PRD found under `_bmad-output/planning-artifacts/prds/`).
- **Working mode**: Coaching path, entry point = Vision + Features (capability-first).
- **Stakes**: Launch-grade — "actually launch" (user's words). Full rigor expected.
- **Core idea (from brain dump)**: A people-first, navigable hierarchy of real Indian politicians (org-chart / Microsoft-Teams-style drill up/down through reporting chains, showing real person data — photo, bio, party, constituency at each node), combined with a historical/time dimension allowing the user to view who held which post going back to 1947 (e.g. "show me the structure as it looked in 1991").
- **Relationship to existing code**: User confirmed this builds on / may edit `power-structure/` (currently static institutional hierarchy with *current* office-holder only), `timeline/` (chronological event feed, not officeholder tenures), and `PoliticalRelationshipMap` (party/alliance graph, not personal org-chart). None of these currently support historical time-travel or full personal drill-down — this is new ground, not a tweak.
- **Audience**: "For everyone" — same general public/curious-citizen audience as the rest of LokTantra, no narrower audience named.
- **Vision locked (§1)**: "Power Explorer" — a graph-based visual encyclopedia of power. Select any politician/post/institution and see career path, reporting chains, responsibilities, and constitutional grounding unfold as a connected graph with real people/photos/current data; rewind through time to 1947. Core reframe: replaces civics memorization with graphical discovery, and makes the Constitution tangible by anchoring it to real people and structures. User confirmed this draft as-is ("Continue").
- **JTBD locked (§2.1)**: Functional only — "understand how government actually works beyond the textbook." User picked this directly from the offered angles; emotional/social/contextual not pursued as primary.
- **UJ-1 locked**: Aman / Cabinet-reshuffle session, confirmed as-is ("yes").
- **Platform decision**: Mobile-first (user confirmed directly) — this has real weight given the graph-heavy, exploration-driven UX; downstream UX/architecture should treat mobile as the primary canvas, not an afterthought.
- **UJ-2 drafted and adjusted**: Priya / schoolteacher, historical time-travel session.
  - Snapshot/bookmark-a-moment-in-time: user said **not a priority for now** → flagged as `[NON-GOAL for MVP]`, to be carried into §6.2.
  - Time-travel scrubber: user chose **continuous** (any date), not anchored-to-known-transitions.
  - **Gap-handling resolved**: when the scrubber lands between two known transitions, the system shows the **last known state as of that date** (most recent recorded change before the selected date). This becomes a testable consequence on the relevant time-travel FR in §4 — not deferred to an open question.
- **Feature set confirmed (§4 scaffold)**: Power Graph, Person/Node Profiles, Constitutional Grounding, Time Travel, Search & Discovery. User confirmed as correct, no additions/removals.
- **Scope decision — graph depth & profile breadth**: User initially selected the most ambitious options for both (full depth incl. individual MPs/MLAs/constituencies; full profile incl. structural+accountability+activity data). PM flagged the data-sourcing implications (28 states + 8 UTs, historical depth to 1947, ongoing activity-data maintenance) as closer to platform ceiling than v1. User explicitly delegated the sequencing call ("Choose the most appropriate way").
- **MVP slice — PM's call, user-approved ("Okay")**:
  - **In**: National/central layer only (President, PM, Union Cabinet/Ministers, central institutions, judiciary apex). Profile depth = structural facts + accountability data (ADR/MyNeta — assets, criminal cases, election history). Continuous time-travel to 1947 for this layer.
  - **Deferred (north-star, not v1)**: state governments (CMs, state cabinets), individual MPs/MLAs/constituencies, and activity-level profile data (voting records, speeches, public statements) — each its own expansion wave.
  - **Rationale**: delivers the *complete* core experience (graph nav + real profiles + constitutional grounding + time-travel) at a buildable scope; every later wave extends the same shape rather than introducing a new kind of feature.
- **Glossary + Features drafted (§3, §4)**: 9 terms, 5 features, FR-1 through FR-8. User asked PM to resolve 3 flagged assumptions:
  - **FR-3 (career path → Time Travel link)**: PM chose to **link them** — tapping a career-path step jumps Time Travel to that period. Rationale: reinforces "graph in motion" vision, avoids a disconnected mini-timeline mental model, directly serves UJ-2. Resolved into FR-3 as a confirmed consequence (no longer an `[ASSUMPTION]`).
  - **FR-1/FR-7 (performance budget)**: left as an open question for §8 — not a PM call to make; architecture must set the number.
  - **FR-8 (search reuses `/api/search`)**: kept as a stated assumption for architecture to confirm/override — sensible default given existing LokTantra search conventions, but not locked.

Directly enforces `CLAUDE.md`'s "politically neutral" principle — flagged as non-negotiable given this feature visually maps real politicians/parties.
